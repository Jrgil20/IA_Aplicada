## 1. Problem Statement

During the initial run of `classify_tickets.py` generated by OpenCode on the DGX Spark environment, the validation commands returned abnormal metrics:

```text
Total tickets processed: 85
Urgencias: {'media': 85}
Categorias: {'otro': 85}
Duplicados detectados: 84
```

This indicated two major failures in the automation logic:
1. **False Duplicate Saturation (84 duplicates out of 85 tickets).**
2. **LLM Classification Fallback Saturation (100% categorized as `otro`/`media`).**

---

## 2. Root Cause Analysis

### Issue A: Duplicate Detection on Empty/Missing Descriptions
- **Cause:** Several rows in `tickets_tramontana.csv` lack a `Descripción del problema` column value (empty strings).
- **Mechanism:** The naive text normalizer stripped whitespace and punctuation from empty values, returning `""`. Since `""` was already registered in the `seen` hash table after the first empty ticket, every subsequent empty or whitespace-only description was flagged as `es_duplicado: true`.
- **Impact:** 84 tickets were erroneously classified as duplicates of one another.

### Issue B: JSON Parsing Failures from LLM Output
- **Cause:** `llama-server` and chat-tuned instruction models (such as Qwen) frequently wrap JSON outputs in Markdown code blocks:
  ````markdown
  ```json
  {
    "categoria": "tecnico",
    "urgencia": "alta",
    "resumen": "Sistema caído en almacén."
  }
  ```
  ````
- **Mechanism:** Calling `json.loads()` directly on this output threw a `json.decoder.JSONDecodeError`.
- **Impact:** The exception handler silently caught the error and triggered the default fallback values (`categoria: "otro"`, `urgencia: "media"`), causing all 85 tickets to appear identical in categories and urgency.

---

## 3. Implemented Fixes & Architectural Decisions

### 1. Robust Duplicate Filtration
- Added a threshold check: Only non-empty strings with a normalized length greater than 10 characters are evaluated for duplicates.
- Empty descriptions are explicitly exempt from duplicate flagging and instead fall back to using the `Asunto` column for semantic context.

```python
norm_desc = normalize_text(raw_desc)
if not norm_desc or len(norm_desc) < 10:
    duplicate_flags.append(False)
else:
    if norm_desc in seen_texts:
        duplicate_flags.append(True)
    else:
        seen_texts[norm_desc] = True
        duplicate_flags.append(False)
```

### 2. Markdown Code-Block Sanitization
- Implemented regex stripping of leading and trailing triple-backtick markdown blocks prior to calling `json.loads`:

```python
if content.startswith("```"):
    content = re.sub(r"^```(?:json)?\s*", "", content)
    content = re.sub(r"\s*```$", "", content)
```

### 3. Graceful Classification Degradation
- Validated categories against `{"facturacion", "tecnico", "ventas", "otro"}` and urgencies against `{"baja", "media", "alta"}`.
- Tickets failing network or parsing stages are classified as `"sin_clasificar"` rather than silently masked as valid categories.
